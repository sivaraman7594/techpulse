## 3. Supervised Learning Algorithms

### Linear regression
<!-- level: basic; ref: https://scikit-learn.org/stable/modules/linear_model.html -->
Linear regression predicts a number as a weighted sum of features plus an intercept: prediction = w1*x1 + w2*x2 + ... + b. Training finds weights that minimise mean squared error, either with a closed-form solution (ordinary least squares) or with gradient descent for large data.

Why it matters: it is fast, interpretable (each weight is the change in prediction per unit of that feature, holding others fixed) and a strong baseline. Many complex models are judged against it.

Key assumptions: a roughly linear relationship, independent errors with constant variance, and limited multicollinearity (highly correlated features make individual weights unstable even when predictions are fine).

Extending it: add non-linear features (polynomials, logs, interactions, splines) while keeping the model linear in its parameters; add regularisation (Ridge, Lasso) to control overfitting.

```python
from sklearn.linear_model import LinearRegression, Ridge
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler, PolynomialFeatures
from sklearn.metrics import mean_absolute_error

lin = LinearRegression().fit(X_train, y_train)
print(dict(zip(feature_names, lin.coef_.round(2))), lin.intercept_)

poly = make_pipeline(PolynomialFeatures(degree=2, include_bias=False),
                     StandardScaler(), Ridge(alpha=1.0)).fit(X_train, y_train)
print(mean_absolute_error(y_test, poly.predict(X_test)))
```

For skewed targets like prices, modelling `log(price)` often fits better and turns errors into relative ones.

#### Pitfalls
- Interpreting coefficients causally ("increasing ad spend by 1 raises sales by w") is unjustified from observational data.
- Comparing coefficient magnitudes is meaningful only when features are on the same scale.
- Outliers can dominate a squared-error fit; check residual plots.

### Logistic regression
<!-- level: basic; ref: https://developers.google.com/machine-learning/crash-course/logistic-regression -->
Despite its name, logistic regression is a classification algorithm. It computes a linear score (w . x + b), then passes it through the sigmoid function to produce a probability between 0 and 1. It is trained by minimising log loss (cross-entropy), which is convex, so optimisation reliably finds the global optimum.

Interpretation: each coefficient changes the log-odds. Exponentiating a coefficient gives an odds ratio: a weight of 0.7 means the odds multiply by about 2 per unit increase of that feature.

Multi-class problems use softmax (multinomial) regression, which generalises the sigmoid to many classes.

Why it remains popular: fast to train and serve, produces reasonably calibrated probabilities, easy to explain to regulators (common in credit scoring), and a strong baseline for text classification with TF-IDF features.

```python
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
import numpy as np

clf = make_pipeline(StandardScaler(),
                    LogisticRegression(C=1.0, class_weight="balanced", max_iter=1000))
clf.fit(X_train, y_train)
proba = clf.predict_proba(X_test)[:, 1]          # probability of positive class
preds = (proba >= 0.3).astype(int)               # custom threshold, not just 0.5

coefs = clf[-1].coef_[0]
print(sorted(zip(np.exp(coefs).round(2), feature_names), reverse=True)[:5])  # odds ratios
```

In scikit-learn, `C` is the inverse of regularisation strength: smaller C means stronger regularisation. Regularisation is on by default (L2).

#### Pitfalls
- It draws a linear decision boundary; non-linear relationships need engineered features or a different model.
- Perfectly separable data makes unregularised weights grow without bound.

### Decision trees
<!-- level: basic; ref: https://scikit-learn.org/stable/modules/tree.html -->
A decision tree predicts by asking a sequence of yes/no questions about features ("tenure < 6 months?", "plan = basic?") until it reaches a leaf with a prediction. Training is greedy: at each node it chooses the split that most reduces impurity (Gini or entropy for classification, variance for regression), then recurses on each branch.

Strengths:

- Captures non-linear relationships and interactions automatically.
- No feature scaling needed; handles mixed feature types.
- Small trees are easy to visualise and explain as rules.

Weaknesses:

- High variance: small changes in data can produce a completely different tree.
- Deep trees overfit by memorising training data.
- Axis-aligned splits approximate diagonal boundaries clumsily.

Control complexity with `max_depth`, `min_samples_leaf`, `min_samples_split` or cost-complexity pruning (`ccp_alpha`).

```python
from sklearn.tree import DecisionTreeClassifier, export_text

tree = DecisionTreeClassifier(max_depth=4, min_samples_leaf=50, random_state=0)
tree.fit(X_train, y_train)
print(export_text(tree, feature_names=list(feature_names)))
print(tree.score(X_val, y_val))
```

Single trees are rarely the best performers, but they are the building blocks of random forests and gradient boosting, which dominate tabular ML.

#### Interview tip
- Explain why trees need no scaling: splits depend only on the ordering of values within a feature, not on their magnitude.

### Random forests and bagging
<!-- level: intermediate; ref: https://scikit-learn.org/stable/modules/ensemble.html#random-forests-and-other-randomized-tree-ensembles -->
Bagging (bootstrap aggregating) reduces variance by training many models on bootstrap samples (random samples with replacement) of the training data and averaging their predictions. Errors of individual models partially cancel out.

A random forest is bagging applied to decision trees with one extra trick: at each split, only a random subset of features is considered (`max_features`). This decorrelates the trees, so averaging them reduces variance much more than plain bagging.

Properties:

- Strong out-of-the-box performance on tabular data with little tuning.
- Robust to outliers and irrelevant features; no scaling needed.
- Out-of-bag (OOB) score: each tree skips about a third of the data, which serves as a free validation set.
- Parallelises trivially across trees.

Trade-offs: larger models and slower predictions than a single tree; probabilities are often poorly calibrated; less accurate than well-tuned gradient boosting on many tabular benchmarks.

```python
from sklearn.ensemble import RandomForestClassifier

rf = RandomForestClassifier(
    n_estimators=500, max_features="sqrt", min_samples_leaf=5,
    oob_score=True, n_jobs=-1, random_state=0)
rf.fit(X_train, y_train)
print("OOB accuracy:", rf.oob_score_)
```

More trees never hurt accuracy (they just cost compute); the important knobs are `max_features`, `min_samples_leaf` and `max_depth`.

#### Pitfalls
- Impurity-based feature importances (`feature_importances_`) are biased toward high-cardinality and continuous features; prefer permutation importance on a validation set.
- Random forests cannot extrapolate beyond the target range seen in training, which matters for trending time series.

### Gradient-boosted trees
<!-- level: intermediate; ref: https://scikit-learn.org/stable/modules/ensemble.html#histogram-based-gradient-boosting -->
Boosting builds an ensemble sequentially: each new small tree is trained to correct the errors of the ensemble so far. In gradient boosting, each tree fits the negative gradient of the loss (for squared error, the residuals), and its contribution is scaled by a learning rate. Many weak learners combine into a very strong one.

Gradient-boosted decision trees (GBDTs) are usually the best-performing models for structured, tabular data, and they power many ranking, risk and forecasting systems. Popular implementations: XGBoost, LightGBM, CatBoost, and scikit-learn's `HistGradientBoostingClassifier/Regressor`, which bins features into histograms for speed and handles missing values and categorical features natively.

Key hyperparameters:

- `learning_rate` and number of trees: lower learning rates need more trees but generalise better.
- Tree complexity: `max_depth` or `max_leaf_nodes`, `min_samples_leaf`.
- Regularisation: L2 penalty, subsampling rows and columns.
- Early stopping: stop adding trees when validation loss stops improving.

```python
from sklearn.ensemble import HistGradientBoostingClassifier

gb = HistGradientBoostingClassifier(
    learning_rate=0.05, max_iter=2000, max_leaf_nodes=31, l2_regularization=1.0,
    early_stopping=True, validation_fraction=0.1, n_iter_no_change=50,
    categorical_features="from_dtype", random_state=0)
gb.fit(X_train, y_train)          # pandas 'category' columns used natively
print(gb.n_iter_, gb.score(X_val, y_val))
```

#### Pitfalls
- Boosting can overfit noisy labels if run too long; always use early stopping on a proper validation set.
- Tuning everything at once wastes time. Fix a modest learning rate, tune tree size and regularisation, then let early stopping pick the number of trees.

### k-nearest neighbours
<!-- level: basic; ref: https://scikit-learn.org/stable/modules/neighbors.html -->
k-nearest neighbours (k-NN) makes predictions by finding the k training examples closest to the input and taking a majority vote (classification) or average (regression). There is no real training phase; the model is the stored dataset. It is called a lazy, instance-based method.

Important choices:

- k: small k gives flexible but noisy boundaries (overfitting); large k smooths them (underfitting). Choose by cross-validation.
- Distance metric: Euclidean is the default; cosine distance suits text and embeddings; Manhattan can be more robust.
- Weighting: `weights="distance"` lets closer neighbours count more.
- Scaling: essential, because distance is dominated by features with large ranges.

Limitations: prediction cost grows with dataset size (tree indexes help in low dimensions), memory holds the entire training set, and in high dimensions distances become less meaningful (the curse of dimensionality).

```python
from sklearn.neighbors import KNeighborsClassifier
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.model_selection import GridSearchCV

pipe = make_pipeline(StandardScaler(), KNeighborsClassifier())
search = GridSearchCV(pipe, {"kneighborsclassifier__n_neighbors": [3, 5, 11, 21],
                             "kneighborsclassifier__weights": ["uniform", "distance"]}, cv=5)
search.fit(X_train, y_train)
print(search.best_params_, search.score(X_test, y_test))
```

The same nearest-neighbour idea, scaled up with approximate search, is the heart of semantic search and retrieval-augmented generation over embeddings.

#### Pitfalls
- Forgetting to scale features silently ruins k-NN results.
- Exact k-NN on millions of high-dimensional vectors is too slow for real-time use; use approximate nearest neighbour indexes.

### Support vector machines
<!-- level: intermediate; ref: https://scikit-learn.org/stable/modules/svm.html -->
A support vector machine (SVM) finds the decision boundary that separates classes with the widest possible margin. Only the training points closest to the boundary, the support vectors, determine it. The parameter `C` controls the trade-off between a wide margin and classifying training points correctly: small C tolerates more errors (stronger regularisation), large C fits training data tightly.

The kernel trick lets SVMs learn non-linear boundaries. A kernel computes similarity as if data were mapped into a higher-dimensional space without computing that mapping explicitly. Common kernels: linear, polynomial and RBF (Gaussian), where `gamma` controls how far each point's influence reaches.

When SVMs fit well: small to medium datasets with many features, such as text classification with sparse features (a linear SVM is fast and strong) or problems where clear margins exist.

Limitations: kernel SVMs scale poorly (training time grows roughly quadratically or worse with samples), they need feature scaling, and they do not output probabilities natively (`probability=True` adds an expensive calibration step).

```python
from sklearn.svm import SVC, LinearSVC
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.feature_extraction.text import TfidfVectorizer

rbf = make_pipeline(StandardScaler(), SVC(kernel="rbf", C=10, gamma="scale"))
rbf.fit(X_train, y_train)

text_clf = make_pipeline(TfidfVectorizer(ngram_range=(1, 2), min_df=2), LinearSVC(C=0.5))
text_clf.fit(train_texts, train_labels)
```

#### Interview tip
- Explain margin and support vectors, the role of C and gamma, and why gradient boosting has largely replaced SVMs for tabular data while linear SVMs remain strong for sparse text.

### Naive Bayes
<!-- level: basic; ref: https://scikit-learn.org/stable/modules/naive_bayes.html -->
Naive Bayes classifiers apply Bayes' rule with a strong simplifying assumption: features are conditionally independent given the class. The model multiplies, for each class, the prior probability of the class by the probability of each feature value given that class, and predicts the class with the highest result (in practice, summing log-probabilities to avoid numerical underflow).

The independence assumption is almost always false (words in an email are correlated), yet the classifier often ranks classes well because it only needs the highest score to be right, not exact probabilities.

Variants match the feature type:

- `MultinomialNB`: word counts or TF-IDF, the classic spam filter.
- `BernoulliNB`: binary word presence.
- `GaussianNB`: continuous features assumed normal within each class.
- `ComplementNB`: often better for imbalanced text classes.

Laplace (additive) smoothing via `alpha` prevents a single unseen word from zeroing a class probability.

```python
from sklearn.naive_bayes import MultinomialNB
from sklearn.feature_extraction.text import CountVectorizer
from sklearn.pipeline import make_pipeline

spam = make_pipeline(CountVectorizer(stop_words="english"), MultinomialNB(alpha=0.5))
spam.fit(train_emails, train_labels)
spam.predict(["Win a free cruise now, click here"])
```

Strengths: trains in one pass, works with very little data, handles huge vocabularies, and supports incremental learning (`partial_fit`). It makes a great baseline for text tasks before trying transformers.

#### Pitfalls
- Its predicted probabilities are usually overconfident (pushed toward 0 or 1); calibrate them if you use probabilities directly.
- Strongly correlated or duplicated features get counted multiple times, skewing predictions.

## 4. Unsupervised Learning

### k-means clustering
<!-- level: basic; ref: https://scikit-learn.org/stable/modules/clustering.html#k-means -->
k-means groups data into k clusters, each represented by its centroid (mean point). The algorithm alternates two steps until assignments stop changing: assign each point to its nearest centroid, then move each centroid to the mean of its assigned points. It minimises within-cluster sum of squared distances (inertia).

Typical uses: customer segmentation, compressing colours in images, grouping documents by embedding, creating features (cluster id or distance to centroids) for downstream models.

Practical details:

- Initialisation matters; k-means++ (scikit-learn's default) spreads initial centroids and multiple restarts (`n_init`) pick the best run.
- Choose k with the elbow method (inertia vs k), silhouette scores, and above all business usefulness: five interpretable segments may beat eight marginally better ones.
- Scale features first, since the algorithm uses Euclidean distance.
- `MiniBatchKMeans` handles large datasets.

```python
from sklearn.cluster import KMeans
from sklearn.preprocessing import StandardScaler
from sklearn.metrics import silhouette_score

X_scaled = StandardScaler().fit_transform(customers[["recency", "frequency", "monetary"]])
for k in range(2, 9):
    km = KMeans(n_clusters=k, n_init=10, random_state=0).fit(X_scaled)
    print(k, round(km.inertia_), round(silhouette_score(X_scaled, km.labels_), 3))

customers["segment"] = KMeans(n_clusters=4, n_init=10, random_state=0).fit_predict(X_scaled)
print(customers.groupby("segment")[["recency", "frequency", "monetary"]].mean())
```

#### Pitfalls
- k-means assumes roughly spherical, similarly sized clusters; elongated or nested shapes are split wrongly.
- Every point is forced into a cluster, including outliers, which also drag centroids.
- Cluster labels are arbitrary numbers that change between runs; map them to profiles before using them in production.

### Density-based and hierarchical clustering
<!-- level: intermediate; ref: https://scikit-learn.org/stable/modules/clustering.html#dbscan -->
When clusters are not round or the number of clusters is unknown, other families work better.

Density-based clustering (DBSCAN, HDBSCAN) defines clusters as dense regions separated by sparse ones. DBSCAN uses two parameters: `eps` (neighbourhood radius) and `min_samples` (points needed to form a dense core). Points in sparse areas are labelled noise (-1) instead of being forced into a cluster. It finds arbitrary shapes and naturally flags outliers. HDBSCAN (in scikit-learn since 1.3) removes the need for a single global `eps` and handles clusters of varying density, making it a strong default.

Hierarchical (agglomerative) clustering starts with each point as its own cluster and repeatedly merges the closest pair, producing a tree (dendrogram). Cutting the tree at different heights gives different numbers of clusters. The linkage criterion (ward, average, complete, single) defines "closest". It is easy to interpret but scales poorly to very large datasets.

```python
from sklearn.cluster import DBSCAN, HDBSCAN, AgglomerativeClustering

labels = DBSCAN(eps=0.3, min_samples=10).fit_predict(X_scaled)
print("clusters:", len(set(labels)) - (1 if -1 in labels else 0),
      "noise points:", (labels == -1).sum())

labels_h = HDBSCAN(min_cluster_size=25).fit_predict(X_scaled)

agg = AgglomerativeClustering(n_clusters=None, distance_threshold=5.0, linkage="ward")
labels_a = agg.fit_predict(X_scaled)
```

Evaluating clusters without labels is hard. Combine internal metrics (silhouette), stability across samples, and domain review of cluster profiles.

#### Pitfalls
- DBSCAN's `eps` is sensitive to scale and dimensionality; a k-distance plot helps choose it.
- In high dimensions all distances look similar; reduce dimensionality (PCA, or use good embeddings) before density clustering.

### Principal component analysis
<!-- level: intermediate; ref: https://scikit-learn.org/stable/modules/decomposition.html#pca -->
Principal component analysis (PCA) finds new axes, called principal components, that are linear combinations of the original features, ordered by how much variance in the data they capture. The first component is the direction of greatest spread, the second is the next greatest while being orthogonal to the first, and so on. Keeping only the top components compresses data while retaining most of its information.

Under the hood, PCA centres the data and computes a singular value decomposition (equivalently, the eigenvectors of the covariance matrix).

Uses:

- Dimensionality reduction to speed up models or reduce noise.
- Removing multicollinearity: components are uncorrelated.
- Visualisation by projecting to 2 or 3 dimensions.
- Compression of embeddings for cheaper storage and search.

```python
from sklearn.decomposition import PCA
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
import numpy as np

pca = make_pipeline(StandardScaler(), PCA(n_components=0.95))   # keep 95% of variance
X_reduced = pca.fit_transform(X_train)
p = pca[-1]
print(X_train.shape[1], "->", p.n_components_)
print(np.cumsum(p.explained_variance_ratio_).round(3))
```

Inspect `components_` (loadings) to see which original features drive each component.

#### Pitfalls
- PCA is sensitive to scale; standardise features unless they share units.
- It captures only linear structure, and maximum variance is not the same as maximum relevance to your target; an important but low-variance signal can be discarded.
- Components are harder to explain to stakeholders than original features.

### t-SNE and UMAP for visualisation
<!-- level: intermediate; ref: https://scikit-learn.org/stable/modules/manifold.html#t-sne -->
t-SNE and UMAP are non-linear dimensionality reduction techniques mainly used to visualise high-dimensional data (embeddings, single-cell data, image features) in two dimensions. They aim to preserve local neighbourhoods: points that are close in the original space should stay close in the plot.

How they work, roughly: t-SNE converts distances into probabilities of being neighbours in the high-dimensional and low-dimensional spaces and minimises the difference between them; its `perplexity` parameter sets the effective number of neighbours. UMAP builds a neighbourhood graph and optimises a low-dimensional layout of that graph; it is faster, scales better and tends to preserve more global structure. UMAP is provided by the separate `umap-learn` package.

```python
from sklearn.manifold import TSNE
from sklearn.decomposition import PCA
import matplotlib.pyplot as plt

X50 = PCA(n_components=50).fit_transform(embeddings)       # common pre-step for speed
X2 = TSNE(n_components=2, perplexity=30, init="pca", random_state=0).fit_transform(X50)
plt.scatter(X2[:, 0], X2[:, 1], c=labels, s=3, cmap="tab10")

# import umap
# X2u = umap.UMAP(n_neighbors=15, min_dist=0.1, random_state=0).fit_transform(embeddings)
```

They are excellent for exploration: checking whether embedding models separate classes, spotting mislabelled data or discovering sub-groups.

#### Pitfalls
- Cluster sizes and distances between clusters in a t-SNE plot are not meaningful; do not draw quantitative conclusions from them.
- Results change with hyperparameters and random seeds; try several settings before trusting a pattern.
- t-SNE has no general `transform` for new points, so it is not a feature engineering step for production models.

### Anomaly detection
<!-- level: intermediate; ref: https://scikit-learn.org/stable/modules/outlier_detection.html -->
Anomaly detection finds rare observations that differ from normal behaviour: fraudulent transactions, failing machines, intrusions, data quality errors. Labels are usually scarce, so methods often learn what "normal" looks like and flag deviations.

Approaches:

- Statistical rules: z-scores, interquartile range, seasonal baselines for time series. Simple and explainable.
- Isolation Forest: random trees isolate points with random splits; anomalies are isolated in fewer splits, giving shorter path lengths.
- Local Outlier Factor (LOF): compares a point's local density to its neighbours'.
- One-class SVM: learns a boundary around normal data.
- Reconstruction-based: autoencoders or PCA reconstruct normal data well; high reconstruction error suggests an anomaly.
- Supervised classification when you have enough labelled anomalies, usually the most accurate option.

```python
from sklearn.ensemble import IsolationForest

iso = IsolationForest(n_estimators=300, contamination="auto", random_state=0)
iso.fit(X_train_normal)                       # mostly normal history
scores = -iso.score_samples(X_new)            # higher = more anomalous
alerts = X_new[scores > np.quantile(scores, 0.995)]   # alert budget: top 0.5%
```

Operational design matters as much as the algorithm: set thresholds by alert budget (how many alerts the team can review), route alerts to humans, collect their feedback as labels, and gradually move toward supervised models.

#### Pitfalls
- "Anomalous" is not the same as "interesting": new products, holidays or marketing campaigns create legitimate anomalies. Include context features like seasonality.
- Without any labels, evaluation is guesswork; label a sample of flagged and unflagged cases to estimate precision and recall.
